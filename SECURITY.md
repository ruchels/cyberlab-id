# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

Only the latest stable release receives security updates. Users are encouraged to stay on the most recent version.

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it responsibly via email:

**Email:** [ruchelafwa@gmail.com](mailto:ruchelafwa@gmail.com)

When reporting, please include:

- A clear description of the vulnerability
- Steps to reproduce the issue
- Affected version(s)
- Potential impact assessment
- Any suggested fix or mitigation (optional)

> [!IMPORTANT]
> **Do NOT open a public GitHub issue for security vulnerabilities.** Use the private email channel above to prevent premature disclosure.

## Response Timeline

| Stage                  | Timeframe          |
| ---------------------- | ------------------ |
| Acknowledgement        | Within 48 hours    |
| Initial Assessment     | Within 5 days      |
| Status Update          | Within 14 days     |
| Fix / Patch Release    | Within 30 days     |
| Public Disclosure      | After fix is released |

We will keep you informed throughout the process and credit you in the advisory (unless you prefer to remain anonymous).

## Scope

The following are **in scope** for vulnerability reports:

- Source code in this repository
- Dependencies directly used by the project
- Configuration files and deployment scripts included in the repository
- Authentication, authorization, and data-handling logic

The following are **out of scope**:

- Third-party services or platforms not maintained by this project
- Social engineering attacks against contributors or maintainers
- Denial-of-service (DoS) attacks against hosted instances
- Vulnerabilities in outdated or unsupported versions

## Responsible Disclosure

We follow a responsible disclosure model:

1. **Report privately** — Use the email address above; do not disclose publicly.
2. **Allow time to fix** — Give maintainers a reasonable window (up to 30 days) to address the issue before any public disclosure.
3. **Coordinate disclosure** — We will work with you to publish a coordinated advisory once a fix is available.
4. **Credit** — Reporters will be acknowledged in release notes and security advisories unless they opt out.

We ask that researchers act in good faith, avoid accessing or modifying other users' data, and limit testing to what is necessary to demonstrate the vulnerability.
